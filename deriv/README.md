# deriv/: symbolic derivations of the generated matrices

Some matrix functions in `src/Matrix/` are written by a Wolfram Language script in this
directory. They sit in the matrix file of their system, between the lines
`# generated by symbolic computation (Mathematica)` and `# end of generated code`; the rest of the file is
hand-written, and a script finds its block by the function it holds. The script derives the quasi-linear system covariantly from its tensor equations,
runs its own consistency checks, and rewrites the block only if every check passed (exit status 1
otherwise). Do not edit a generated block by hand: change the script and regenerate.

| script | writes | system |
|---|---|---|
| `derive_2p1d_viscous.wls` | `two_d_viscous_matrix_derived` in `2d_viscous.jl` | Israel–Stewart viscous hydro plus the DNMR term δ_ππ, 2+1D Cartesian Milne (and 1+1D cylindrical as the control) |
| `derive_hq_2p1d.wls` | `two_d_HQ_BG_matrix`, `two_d_HQ_live_rows` in `2d_viscous_HQ_BG.jl` | charm first moment (α, ν^x, ν^y) on a prescribed 2+1D background, Fick closure |
| `derive_two_way.wls` (+ `_gates`, `_export`) | `one_d_HQ_BG_consistent_matrix`, `one_d_HQ_BG_m2_matrix`, `two_d_HQ_BG_consistent_matrix`, `two_d_HQ_BG_m2_matrix`, `one_d_two_way_matrix(_conformal)`, `two_d_two_way_matrix(_conformal)`, `one_d_two_way_cM_matrix(_conformal)`, `two_d_two_way_cM_matrix(_conformal)` | charm first moment (consistent closure) and second moment on a prescribed background, the two-way coupled system (charm in the total T^{μν}), and the fully coupled system (the second moment in T^{μν} too, c_M = D_s/T); 1+1D cylindrical and 2+1D Cartesian; EOS kept symbolic |
| `derive_1d_matrices.wls` | nothing in `src/` | the hand-written 1+1D matrices, compared with their files: `one_d_viscous_matrix`, `one_d_viscous_matrix_fugacity` (`:MIS`), `one_d_viscous_matrix_gamma`, `one_d_viscous_matrix_fugacity_BG_only`, `one_d_ideal_matrix_ruwen4`, `one_d_ideal_matrix_ruwen5` |
| `derive_upstream.wls` | nothing in `src/` | the matrices no solver path relies on, compared with their files: `two_d_viscous_matrix` (ten entries wrong, kept for `legacy = true`), `two_d_viscous_HQ_matrix`, `one_d_ideal_matrix_ruwen7`, `one_d_ideal_matrix_ruwen6` |
| `derive_drivers.wls` | nothing in `src/` | what the drivers add: κ and τ_n, the charm closures, the regulators, the cold edge, the corona update; it runs `audit_matrices.jl` |

`audit_matrices.jl` is a second, independent route: it rebuilds every system numerically with ForwardDiff from
the tensor equations, sharing no code with the Wolfram scripts, compares the solved form with each kernel, calls
each driver at physical states, and evaluates the corona update on a grid.

Helper: `julia_source_reader.wl` reads a matrix out of a `.jl` file in `src/Matrix/`, so the
scripts can compare their result with the code itself rather than with a hand transcription, and
writes the generated block back.

## How each derivation is checked

Each script compares its own result against an independent known answer before it writes anything:

- the cylindrical (1+1D) reduction must reproduce the existing hand-written 1-D matrix entry by
  entry (`one_d_viscous_matrix`, `one_d_viscous_matrix_fugacity_BG_only`), read from the `.jl`
  file;
- metric compatibility, transversality and tracelessness of every constructed tensor hold
  identically;
- the system is quasi-linear (no second derivatives survive);
- the Bjorken and slab limits reduce to the known 0+1D and decoupled equations, and the 2+1D
  systems reduce to the 1+1D ones on axisymmetric flow;
- the charm rows of the hand-written 7-field and ideal matrices are the derived rows with ∂_τ of the
  medium eliminated with the medium rows, raw, exactly;
- for the two-way system, the fluid rows equal ∇_μ(T_m + T_Q)^{μν} computed by an independent
  route, the second moment is passive, and there is no momentum exchange at rest.

The Julia tests in `test/` check the generated functions against closed forms.

## Running

Requires Mathematica / `wolframscript` (no extra packages). From the package root:

```sh
wolframscript -file deriv/derive_2p1d_viscous.wls          # seconds
wolframscript -file deriv/derive_hq_2p1d.wls
wolframscript -file deriv/derive_two_way.wls               # ~5 min; --charts=bj,cyl,car
wolframscript -file deriv/derive_1d_matrices.wls           # seconds
wolframscript -file deriv/derive_upstream.wls              # seconds
wolframscript -file deriv/derive_drivers.wls               # ~3 min, most of it Julia
```

A regeneration with unchanged scripts is byte-identical to the committed files.
`FLUIDUM_DERIV_RENDER=1` also writes the rendered derivation into `rendered/` (see below).
`derive_two_way.wls` uses a scratch directory, `TWOWAY_OUT` (default
`$TemporaryDirectory/derive_two_way_out`), and runs Julia for two of its checks in the project
`FLUIDUM_DERIV_PROJECT` (default the package root); `derive_drivers.wls` runs `audit_matrices.jl` in
the same project, which needs Fluidum, StaticArrays and ForwardDiff. `derive_1d_matrices.wls` writes its reference
states, `matrix_refpoints_1d.csv`, only when `FLUIDUM_REFPOINTS_DIR` is set.

## Rendered output

`rendered/` holds the derivations in readable form, written by the scripts themselves from the
matrices, sources and check results they computed:

- `derivations.pdf`: one section per script (setup, steps, every nonzero matrix and source entry,
  the table of checks), and an appendix. `derivations.tex` is the master; `viscous.tex`,
  `hq_2p1d.tex`, `two_way.tex`, `one_d.tex`, `upstream.tex`, `drivers.tex` and `two_way_full.tex` are the
  generated fragments.
- `<name>.nb`: the same content as notebooks, with the script source at the end; written locally,
  not tracked.

The Steps sections show the script's intermediate objects (Christoffels, constraint solutions,
tensor components, the rows) in 1+1D and 2+1D, and check at random exact points
that they assemble into the rows and that the extracted matrices reassemble the rows.

For the two-way script, the 1+1D charm systems and the 1+1D conformal two-way system are written
out in the section; the generic-EOS 1+1D two-way system and all 2+1D systems are shown there as
field layout and sparsity pattern, with their entries in the appendix.

The rendering code is `render.wl`. It is loaded only when `FLUIDUM_DERIV_RENDER=1`; without it
the scripts behave as before. A check's ASCII message is typeset by the rules `rdMsgRules`. Every displayed entry is compared with the derived expression at
random exact points before it is written. To regenerate everything:

```sh
deriv/render_all.sh
```

or one script at a time, then the PDF:

```sh
FLUIDUM_DERIV_RENDER=1 wolframscript -file deriv/<script>.wls
cd deriv/rendered && latexmk -pdf derivations.tex
```
